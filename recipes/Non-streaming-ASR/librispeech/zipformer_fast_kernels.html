Zipformer faster training with fused GPU kernels

This page shows how to make Zipformer training faster, i.e., use less GPU time, with the optional fused GPU kernels in zipformer/fast_kernels.py.

A Zipformer training step is limited by memory bandwidth: most of the GPU time goes to elementwise and copy kernels, not to matrix multiplications. fast_kernels.py replaces the most memory-bound parts of zipformer/scaling.py with fused Triton kernels and cheaper backward functions. They compute the same values as the reference code (up to floating-point rounding) and only change training speed. Decoding, model export and the saved checkpoints are not affected.

Note

The optimizations are off by default. Without the environment variable below, training behaves exactly as before.

Enabling the optimizations

Set the environment variable ZIPFORMER_FAST_KERNELS:

Value

Effect

unset, 0

upstream behaviour (default)

1 or all

enable all features listed below

comma-separated list, e.g., balancer,softmax

enable only the listed features

The features are:

Feature

What it replaces

actlin

ActivationDropoutAndLinear: one Triton kernel computes swoosh(x) * dropout_mask and writes the matmul dtype directly; fused backward

swoosh

SwooshL / SwooshR modules: a Triton kernel that keeps the input dtype (k2.swoosh_l / k2.swoosh_r return float32)

softmax

SoftmaxFunction backward: PyTorch’s fused softmax backward instead of float32 elementwise operations

balancer

BalancerFunction backward: closed-form gradient (two small kernels) instead of re-running a float32 autograd graph

channels_last

Conv2dSubsampling runs in NHWC layout so that cuDNN’s fast depthwise convolution kernels are used

Hint

The optimizations need a CUDA GPU and Triton, which is installed together with PyTorch on Linux. If either is missing, a warning is printed and the reference code is used.

Training

Put the environment variable in front of the usual training command. The following example trains a Zipformer (medium) model with all optimizations on 4 GPUs:

$ cd egs/librispeech/ASR
$ export CUDA_VISIBLE_DEVICES="0,1,2,3"
$ ZIPFORMER_FAST_KERNELS=1 ./zipformer/train.py \
    --world-size 4 \
    --num-epochs 30 \
    --start-epoch 1 \
    --use-fp16 1 \
    --exp-dir zipformer/exp \
    --max-duration 1000

It works the same way for the other model sizes, for example the large model:

$ ZIPFORMER_FAST_KERNELS=1 ./zipformer/train.py \
    --world-size 4 \
    --num-epochs 30 \
    --start-epoch 1 \
    --use-fp16 1 \
    --exp-dir zipformer/exp-large \
    --num-encoder-layers 2,2,4,5,4,2 \
    --feedforward-dim 512,768,1536,2048,1536,768 \
    --encoder-dim 192,256,512,768,512,256 \
    --encoder-unmasked-dim 192,192,256,320,256,192 \
    --max-duration 1000

To enable only some of the optimizations:

$ ZIPFORMER_FAST_KERNELS=balancer,softmax ./zipformer/train.py ...

Decoding

Decoding needs no change; do not set the environment variable:

$ ./zipformer/decode.py \
    --epoch 30 \
    --avg 9 \
    --exp-dir zipformer/exp \
    --max-duration 600 \
    --decoding-method greedy_search

For a model trained with non-default architecture options, pass the same options as in training, e.g., for the large model above:

$ ./zipformer/decode.py \
    --epoch 30 \
    --avg 9 \
    --exp-dir zipformer/exp-large \
    --num-encoder-layers 2,2,4,5,4,2 \
    --feedforward-dim 512,768,1536,2048,1536,768 \
    --encoder-dim 192,256,512,768,512,256 \
    --encoder-unmasked-dim 192,192,256,320,256,192 \
    --max-duration 600 \
    --decoding-method greedy_search

Testing the kernels

zipformer/test_fast_kernels.py compares every replacement against the reference implementation in scaling.py in float32 and bfloat16 (a GPU is required):

$ cd egs/librispeech/ASR
$ python3 ./zipformer/test_fast_kernels.py
